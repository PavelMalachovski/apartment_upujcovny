# Промпт: 3D-тур по квартире из фотографий за один заход

Скопируй текст ниже в Claude Code, приложив папку с фотографиями квартиры
(включая поэтажный план, если есть).

---

В этой папке — фотографии квартиры (одна из них может быть поэтажным
планом). Построй интерактивный браузерный 3D-тур «как ходишь с риэлтором»
и доведи его до продажного качества. Работай автономно, спрашивай только
критичные развилки.

**Стек и архитектура (важно, не отклоняйся):**
- Чистый Three.js (локальная копия, UMD), без сборщиков и CDN
- Все данные квартиры — в JSON-конфиге `apartments/<id>.json`: стены с
  проёмами (двери/окна/проходы), полы по уровням, мансардные скосы,
  лестница, мебель, свет, зоны пола для физики, точки телепорта, площади
  комнат. Углы — в градусах. Код один на все объекты, лоадер по `?apt=<id>`
- Геометрию сними с поэтажного плана; масштаб откалибруй по стандартной
  мебели (кровать 180 см, столешница 60 см, ступень ~20 см)

**Функциональность:**
1. Прогулка от первого лица: WASD, осмотр — drag мышью (НИКОГДА не
   используй pointer lock: курсор должен быть виден, кнопки кликабельны).
   На тач: постоянно видимый джойстик слева + свайп-осмотр справа,
   мультитач. Коллизии (сегменты стен + AABB мебели), подъём по лестнице
   плавным клампом высоты, у низких скатов мансарды прижимай камеру под
   потолок
2. Меню «☰ Комнаты» — телепорт по всем комнатам (работает и на телефоне)
3. Режим макета «⌂» (клавиша M): орбитальная камера, крыша скрыта,
   переключатель «1 этаж / весь дом» (стены запекай в два меша по
   уровням), метки «комната + м²», рулетка (два клика — расстояние),
   клик по полу — телепорт в точку с выходом в прогулку
4. Фото-споты: реальные фотографии (webp ≤1200px, в репо), маркеры-иконки
   в точках съёмки, при приближении кнопка/клавиша F открывает фото поверх
   3D — это главный генератор доверия
5. Мини-карта с планом этажа и позицией, подпись текущей комнаты,
   стартовый оверлей с объяснением ВСЕХ кнопок

**Свет и производительность (это и есть «дорогой» вид):**
- Напиши CPU-лайтмаппер: трассировка видимости по AABB-окклюдерам
  (стены, перекрытия, мебель с высотами). Лампы с мягкими тенями
  (джиттер), окна — площадные источники холодного света, на террасе
  солнце с тенями зданий. Полы/потолки/скаты — лайтмапы (CanvasTexture,
  uv2, MeshBasic), стены — слитая геометрия с повершинным светом.
  Запекание при загрузке ≤2 с с прогрессом
- Всю статичную мебель/рамы/шторы сливай по (материал, этаж) — бюджет
  ≤150 draw calls. Динамических PointLight ≤8. На тач pixelRatio ≤1.6
- Тон: ACESFilmic; материалы — процедурные canvas-текстуры (паркет с
  разнотоном досок, мрамор с мягкими жилами, стёганые изголовья, шторы —
  волнистые плоскости)

**Сначала обмерь план программно, а не на глаз.** Найди линии стен по
тёмным пикселям (PIL/numpy), откалибруй масштаб по мебели известного
размера (обеденный стол ~2.3 м, кухонный остров ~2.4 м) и только потом
задавай координаты. Пересчитай по плану ЧИСЛО комнат и габариты
квартиры целиком — прикидка на глаз даёт ошибку в разы: в первом
проекте так потерялось целое западное крыло с четвёртой спальней, а
квартира вышла на треть короче. Отдельно найди на плане лестницу
(штриховка ступеней со стрелкой подъёма) и проверь, к какому помещению
она примыкает: по фотографиям видно, из какой комнаты виден марш.

**Процесс (обязательный, именно он даёт качество):**
- После каждого блока геометрии смотри результат СКРИНШОТОМ (headless
  браузер) и сверяй с фотографиями покомнатно; расхождения чини сразу.
  Сделай вид сверху без потолков — им ловятся ошибки планировки
- Проходимость проверяй симуляцией ходьбы (зажать W программно, прогнать
  update, проверить координаты): вход в каждую комнату, лестница, терраса.
  Мебель не ближе 0.5 м к дверным проёмам
- Экспортируй debug-API (window.__app) для телепорта камеры в тестах
- При каждом изменении JS поднимай версию `?v=N` у всех скриптов И
  версионируй URL JSON-конфига тем же значением — иначе браузер отдаёт
  старую геометрию из кеша, и правки «не работают». Версию поднимай
  ПОСЛЕ последней правки кода
- Двигая стену, проверяй всё, что к ней крепилось (картины, панели) и
  перечисляй заново плиты перекрытий: забытая плита превращается в
  потолок над лестницей, а картина остаётся висеть в воздухе
- Веди работу через ветки и PR с содержательными описаниями; после мержа
  проверяй прод

**Результат:** страница-каталог объектов + тур, деплой на Vercel
(vercel.json, статика без сборки), README (как добавить квартиру за 4
шага) и CLAUDE.md с архитектурой, перф-бюджетом и чек-листом проверок.

## Почему эти пункты в промпте (уроки первого проекта)

- **Drag-look вместо pointer lock** — с захватом мыши пользователи не
  могли нажать ни одну кнопку и не понимали почему
- **Симуляция ходьбы** — три дверных проёма оказались заблокированы
  мебелью, а «тесты успеха» врали, пока не проверяли конечную точку
- **Скриншот-сверка с фото** — планировка мансарды разошлась с реальностью
  (закрытая комната вместо студии с низкой ТВ-перегородкой)
- **Запечённый свет вскрыл геометрию** — терраса висела ниже потолка
  первого этажа, скаты крыши были перевёрнуты
- **Версии скриптов** — телефоны часами держали старый JS из кеша,
  и «исправленные» баги казались живыми
- **Каталог + JSON-конвейер** — превращает разовую поделку в продукт:
  следующая квартира не требует программиста
- **Программный обмер плана** — глазомер занизил длину квартиры на треть
  и «потерял» четвёртую спальню; лестницу пришлось переносить дважды
- **Версия у JSON-конфига** — без неё браузер часами отдавал старую
  геометрию, и уже исправленные баги выглядели живыми
